# 翻译工作

## 选择最短路径

后端translation.mode与projectTextWorkbooks是已核验的分类。已由后端完成并返回结果时不重复处理。用户本轮明确要找人协作、校对或制作卡片时，不自动执行翻译。

| 输入 | 执行 |
| --- | --- |
| 消息中的文字，无需文件 | 直接给译文；不拉取其他Skill、不检查沙箱、不创建文件 |
| TXT、Markdown、CSV等简单文本文件 | 读取一次，翻译一次，保存同格式副本并回读；不转Word、不渲染、不调用规划或复核模型 |
| Word、PDF、PPT或普通Excel | 仅按需使用office-file-work读取/编辑；遵循整篇或指定范围，实际能力不足时说明限制 |
| 后端明确project-text的XLSX/XLSM | 使用下面的按语言列补译流程 |

项目文本须含User Texts工作表并具备有效语言列；只有语言列、文件名或“电气”字样不足以覆盖后端分类。未知结构仅确认一次；后端已判普通文档时按普通文档执行。普通文件不调用electrical_translation。

## 目标与格式

目标语言采用本轮要求；项目文本只剩一个待补语言列且后端给出inferredTargetLanguage时直接采用。多列不明或普通文件未指定目标时只询问目标语言，不从文件名臆断。

整篇翻译保留原内容层次；局部翻译只改指定段落/页/表/列，其余保持原文。普通Excel保持公式、样式和未指定区域；CSV保持分隔符和记录结构。PDF没有可提取文字、扫描件或图片无法读字时说明当前无视觉/OCR能力，请用户提供文字；不声称已看图。TXT不升级成DOCX，除非用户明确要求。

## 项目文本补译（仅后端未完成的确认任务）

1. 读取实际语言表头，目标列只填原本为空的单元格；已有译文、带*参考列、源列、表头和行序不改。
2. electrical_translation输入payload_json：{"items":[{"id":"本批唯一编号","sourceText":"原文","sourceLanguage":"zh-CN","targetLanguage":"en-US"}]}。每批同一语言对，最多24条、总计12000字符；更小任务一次处理，不主动拆成大量小批。
3. 只接受逐条覆盖ID的非空译文，保持工程占位符、地址、型号、单位和换行。参数格式错误仅纠正一次；服务超时或失败即停止，不重跑整个文件或改用整表重写。
4. 写回副本，回读目标列并核对源列、参考列、表头和行数。未完成部分如实说明，不把原件或部分结果当全部完成。

## 交付与边界

原件只读，结果同格式另存，文件名使用本轮output_prefix；回读后实际上传，deliverables只放真实上传引用。普通文档仅在确有复杂事实核对时调用内容复核，不为小文件增加额外模型调用。当前模型无视觉能力；文字/结构回读不能称为视觉检查。

保持术语、数字、单位、型号、专有名词与用户术语表一致，不增删或润色事实。无法读取、加密、旧格式、宏结构复杂或精确定位失败时说明具体限制；不伪造译文、文件、成功状态或内部链接。
