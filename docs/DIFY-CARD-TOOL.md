# Agent 自主卡片设计

2026-11-02 已在本机 Dify“摸摸鱼”中添加并发布 `design_card`（工具集名称：摸摸鱼卡片制作）。使用 Dify 构建对话补充了规则，随后人工审查并修正矛盾，真实调用已通过。

## 当前能力

Agent 按需求自主构思配色、构图和图形，用制作工具生成 1200×400 的 SVG 插画封面。工具同时返回纸面配色、轮廓和版式；文字由网页准确排版，可编辑、搜索、匹配，公屏卡片仍可点击查看并接取。

这不是照片生图服务，也不执行模型生成的 HTML、CSS 或脚本。当前可画几何、山海、城市、办公物件和趣味插画；任意照片生成、上传背景和自定义字体仍未接入。

链路：网页每轮生成短期凭证 → Agent 调用 `design_card` → 工具返回 SVG 和设计数据的签名 → 后端从真实工具事件验签并保存 → 网页通过受权限保护的图片接口显示。模型最终回复中的同名字段不能冒充工具成品。工具失败时保留旧设计。

## 启动与配置

`.env` 新增以下项目；本机已经配置，密钥不纳入 Git：

```dotenv
CARD_TOOL_SECRET=至少32字符的随机字符串
CARD_TOOL_HOST=0.0.0.0
CARD_TOOL_PORT=8792
```

网页后端与制卡工具必须使用同一 `CARD_TOOL_SECRET`。`npm run dev`（或双击启动网站.cmd）会同时启动两者和前端；未设置密钥时仍可运行原有网页功能。生产环境分别守护 `npm start` 与 `npm run start:card-tool`。

Dify 自定义工具导入 [OpenAPI 文件](dify-card-tool.openapi.json)，挂载到 Agent，使用 [已发布主提示词](DIFY-AGENT-PROMPT.txt)。本机 Docker 中工具地址为 `http://host.docker.internal:8792`；迁移服务器时必须改成 Dify 容器实际可达的工具地址，Linux Docker 通常还需配置 host-gateway，或将工具放进同一私有网络。该端口只供 Dify 使用，不应作为网站公网入口。

## Dify 网络规则

本机 Dify 的 SSRF 代理默认拒绝私有地址。本次在 `ssrf_proxy/squid.conf.template` 的 `http_access deny to_private_networks` 前加入 [精确规则片段](dify-card-tool.squid.conf)，并重载代理：仅允许内部客户端 `POST host.docker.internal:8792/design-card`，保留其他地址、端口、路径和方法的原有阻断。没有启用整台宿主机或整个内网的放行。

本机模板位于 Dify 部署目录，不属于本仓库；片段在此存档供迁移。部署时先按原入口脚本展开模板中的环境变量，再校验 Squid 配置和重载，不要将尚含 `${HTTP_PORT}` 的模板直接作为运行配置。

已核对代理边界：制作接口的无效凭证返回 401；同主机 `/health`、`/other` 和 8080 管理端口仍返回 403。

## 协议与权限

- 工具输入为本轮 `job_token` 和 `design_json`。凭证 10 分钟有效，每轮独立；工具不读取员工数据库、不发布需求。
- 工具返回带签名的 `card_artifact`（SVG、设计参数、内容 ID）。网页后端只接受本轮实际工具结果，验证签名和规范化几何；不接受脚本、任意标签或外部 URL。
- 成品保存在需求记录内。网页公开视图仅传轻量元数据，不发送整份 SVG；通过 `/api/requests/:id/artwork.svg` 按需加载。草稿只对本人可读，发布到公司公屏后与需求共享可见范围。
- 正文修改继续复用封面，不重新生图；确认发布、接取和匿名设置仍由网页业务接口控制。

## 聊天交互

`POST /api/clarify` 增加 `Accept: text/event-stream` 时返回 `status`、`result`、`error` 三类事件；不传时保留原 JSON 接口。进度只来自实际处理和工具事件，不返回思考过程、签名或凭证。收到完整有效结果后才更新卡片。

聊天支持 Markdown、表格、代码和回答复制、Enter 发送、Shift+Enter 换行、停止响应、失败后输入恢复。预览与对话在桌面并列；窄屏按顺序堆叠。修改需求内容和可见范围的表单仍可展开。
