## 1. 先更新主提示词

1. 打开本机 Dify：<http://127.0.0.1:8080>，进入 Agents → 摸摸鱼 → 配置。
2. 备份当前提示词，将 [DIFY-AGENT-PROMPT.txt](DIFY-AGENT-PROMPT.txt) 全文复制到“提示词”。替换旧的“只能澄清需求”规则，不要把两套相反的要求直接叠加。
3. 保留“需求澄清”和“需求卡片”两个 Skill。主提示词负责决定何时调用它们，普通问答不必每轮都进入需求澄清。如果 Skill 仍要求固定输出 Markdown 卡片，应改为“网页调用时遵循主提示词的 JSON 协议”。
4. 点击“发布更新”后，通过独立测试账号的网页或服务 API 验证下方用例。本部署 Community Edition 的预览按钮不可用；右侧“构建”对话会修改配置，不应拿它模拟普通用户聊天。网页通过 API 调用已发布的配置，只保存草稿不会让新规则正式生效。

不要把网页的 Dify API Key 放进提示词或 Skill。网页读取服务端 .env，不需要把密钥再给模型看。

## 2. 工具按需要逐步加

仅靠模型就可以处理邮件草稿、翻译、段落润色、思路整理和 Excel 公式解释。工具用于补足计算、联网信息和文件处理，不是装得越多越好。新版 Agent 可使用插件、自定义 API、MCP 与工作流工具。[Dify 官方介绍](https://dify.ai/blog/introducing-new-dify-agent)

| 能力 | 先配什么 | Agent 的调用规则 |
| --- | --- | --- |
| 准确计算 | Marketplace 的 Maths 或经你验证的计算工具 | 数值运算调用工具，保留表达式和单位；失败时明确说明 |
| 查询公开信息 | Tavily Search/Extract 或可用的搜索插件 | 仅时效性和需验证的公开问题检索；附实际来源链接；搜索词不包含内部资料 |
| 回答公司制度 | 经授权的知识检索或参考文件 | 依据命中文档回答并注明出处；未找到就明确说明 |
| 批量处理 Excel/CSV | 经验证的文件处理工作流，发布为工具 | 对收到的文件进行计算或比对，返回结构化结果与真实可用的文件标识；缺文件先索取 |

计算和联网插件的说明：[Maths](https://github.com/langgenius/dify-official-plugins/tree/main/tools/maths)、[Tavily](https://github.com/langgenius/dify-official-plugins/tree/main/tools/tavily)。搜索工具通常需要该服务自己的 API 凭证，与 Dify 应用密钥不同。

### 添加工具的路径

先检查“摸摸鱼 → 配置 → 工具 → 添加”里已有的工具；本次五项工具均直接从已有列表选择。需要新增服务时，再在插件市场安装所选插件并配置授权。发布更新后通过实际 API 事件确认发生了真实工具调用，不要只在市场安装后就假定 Agent 已能使用。

如果公司知识检索区域仍显示“当前部署未启用”，先由管理员启用对应能力；主提示词写“搜索知识库”不会自动打开这个功能。也可先添加少量已授权的参考文档来验证流程。

## 3. 给工具写清什么时候用

可把以下约束加到主提示词的工具段落，并把工具名称换成实际添加的名称：

```text
普通写作、翻译、概念解释直接回答。
遇到数值计算，优先调用已启用的计算工具，检查表达式、单位和结果。
遇到最新信息或需要核实的公开事实，使用已启用的搜索工具；答案注明真实网址和适用时间。
遇到公司制度，只用已授权的资料和知识检索；没有依据时说明没有找到。
文件任务先检查本轮是否真实收到文件；收到后才调用对应处理工具。
工具成功才说明成功；未配置、无权限、超时、无结果时说明限制，不虚构调用记录。
公开搜索只接收适合公开的查询，不发送内部文档、员工资料或密钥。
所有回答仍包在网页要求的 JSON.reply 中，工具不能替代网页的发布确认。
```

如果使用工作流工具，输入输出要简单：例如输入文件 ID、匹配列、基准表和输出列；输出处理状态、差异数量、摘要、真实文件 ID。服务端注入可信用户身份，不让模型自由指定“操作哪个员工”。

## 4. 按这组问题验收

1. “帮我把这段请假邮件写得礼貌一些……” → 直接给草稿，不生成互助卡。
2. “Excel 怎样统计 A 列非空单元格？” → 直接给公式与表头处理说明。
3. “我想发布需求找同事核对两份名单。” → 澄清基准、匹配方式和交付物，再生成卡。
4. “这张卡改成橙色便签，大圆角，标题醒目。” → 只更新外观，需求文字不被清空。
   也可试：“我的卡片做成海边拍立得”“换成摸鱼表情包气泡卡”“改成山景票根”。
5. “显卡驱动怎么用？” → 普通问答，不误认为“修改卡片”。
6. “发布到公屏并给所有人推送。” → 提示使用网页确认发布，不谎称已经推送。
7. “帮我查询今天的某项公开信息。” → 有搜索工具才给出经检索的来源；未配置时说明限制。
8. 用第二个账号提问 → 不带出第一个账号的对话、草稿或材料。

## 5. 本轮网页的边界

已实现文本对话、自主SVG插画、用户上传背景、草稿与未接取公开卡片编辑、移除恢复，以及材料上传/下载、成果多版本提交和发布者验收。预置图片仍可用，任意CSS仍不接受。完整流程与权限见 [文件上传与交付](FILE-DELIVERY.md)。

勾选AI阅读的材料通过原生文件输入传入；图片以预览图传入视觉模型，文档在当前会话沙箱读取。可回答文件问题、核对表格或根据内容澄清需求；Agent可实际生成或修改Word/Excel/PDF，并通过真实工具事件回传私人下载。背景图不参与阅读。也没有照片生图或新增生图密钥位置，按当前范围继续使用SVG插画或用户上传图片。

不要给本轮 Agent 添加发布需求、接取任务、发奖励或群发通知的写工具。它们需要后端授权与本人确认。模型能给出操作建议，不代表这些动作已经发生。


文件阅读配置：Chat功能中启用文件上传，允许 document/image、local_file；本机当前每轮3个。选择真正具备视觉能力的模型，保留Agent沙箱读取文件的能力。网页服务端自动上传选中材料并维护每用户引用，不需要把客户文件放入Agent全员共享的“文件”或知识库。更新提示词后记得发布，优先采用第九节的材料/背景规则。新版Agent原生文件通道参考 [官方文档](https://docs.dify.ai/en/api-reference/files/upload-file)。

## 6. 办公文件 Skill 与回传配置

本机已发布 `office-file-work`，经审查的导入包为 `docs/dify-skills/office-file-work.zip`，源码及脚本同名目录。Dify“配置 → SKILL → 添加 → 上传skill.zip”，上传同名Skill会更新已有版本；再更新主提示词并发布。`SKILL.generated.md` 保留构建器原稿，实际采用 `SKILL.md` 与 `scripts/office_tools.py`。

本机已在Agent私有 `$HOME/.venv-office` 安装 Pillow、python-docx、openpyxl、pypdf、reportlab，并应用主目录快照。迁移到新Dify环境时需重新准备此venv；Skill压缩包不包含67MB的运行库。工具运行时使用自己的会话目录，只读取本轮授权文件，不遍历公共或其他会话目录。

网页自动下发本轮 `output_prefix`、输入的 `local_file` 下载引用与本对话历史结果引用。模型生成后须实际 `dify-agent file upload PATH`，网页通过真实工具事件接回；不可在reply中伪造下载链接。不要把网页的API密钥放进提示词或Skill。输入图片启用视觉时也要使用下载引用取得字节，工作目录为空不等于未收到附件。

`.env` / `.env.example` 的 `DIFY_TIMEOUT_MS=600000` 给文件工作预留10分钟；服务端未设此项时仍默认180秒。结果命名需带本轮前缀，网页下载时去掉前缀。支持直接生成、下一轮基于最新版本修改、私人历史下载；原件不改，结果不自动公开。

## 站内匹配配置

本机已将独立“摸摸鱼·人员匹配”Workflow升级为AI语义匹配与待发布心情文字审核的双分支，保留preview_matches工具。源DSL为`docs/dify-matching-workflow.yml`，可由`node scripts/build-matching-workflow.mjs`重新生成；工具Schema为`docs/dify-matching-tool.openapi.json`。员工档案仍以本地SQLite为准。硬限制由`shared/matching-eligibility.mjs`执行，模型仅对合格人员的技能标签和经验说明作语义判断，不能突破时间、意愿或接单量约束。当前模型提供方为本机已安装的OpenCode Go / deepseek-v4.1-flash；迁移时先替换为实际可用模型并重新发布。

工作流专用密钥放`.env`的DIFY_MATCHING_API_KEY，地址DIFY_MATCHING_BASE_URL；更新后重启网站。无密钥为明确本地规则模式，已配置但工作流出错会留队列重试。Agent只能预匹配匿名数量，发布确认后才由后端发站内消息；第十二节及后端每轮授权共同约束权限。完整调度、配额和人员信息边界见[MATCHING.md](MATCHING.md)。

心情文字审核使用同一Workflow的review_json分支，输入仅为本人准备公开的一段文字，故障时不发布。主Agent提示词最新版本见[DIFY-AGENT-PROMPT.txt](DIFY-AGENT-PROMPT.txt)，已发布并按help/request/care及careSafety分流；无需把心理对话放进知识库或员工匹配档案。详细数据流、接口、危机边界和当前限制见[CARE.md](CARE.md)。
