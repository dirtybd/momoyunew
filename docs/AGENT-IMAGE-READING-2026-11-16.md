# 电气与文件助手视觉接入

状态：2026-11-16 已发布到公司 Dify，并启用本机网站配置。未新增 API Key，未修改他人的 EPLAN 流程。

## 当前链路

网站授权图片 → 原生视觉 LLM 提取可见事实 → 专业 Agent：

- 电气助手接到型号、故障码、元件/端子、可确认接线和模糊处，再实际调用 electrical_knowledge 检索；区分图片观察、知识库依据与通用建议。图中没有的信息不能补造，不根据单图给出可直接送电的结论。
- 文件助手通过 task_json.imageReadings 取得实际视觉记录，用于内容分析或文件制作，不再以文件头、尺寸、编码冒充画面内容。记录失败、截断或模糊时如实说明，用户更正优先核对。
- 普通无图问答、卡片和关怀分支跳过这一步；普通图片直接问答与卡片自身的原生视觉保留。生成文件的分支仍使用现有办公 Agent 和文件工具。

统一入口新增条件门、视觉读取、变量聚合和任务上下文整理节点。无图路径使用明确回退值，不增加一次模型调用。视觉步骤失败会标注 unreadable，不伪造已读结果。

`/电气` 有本轮授权图片时转入统一入口的电气分支；无图仍保持原有直接 Agent 入口。明确 `/办公`、卡片和情感安全的优先级保留。背景图、报酬图、关闭 AI 阅读、未选择到当前任务的图片继续由后端权限与附件选择逻辑排除。

本机 `.env` 的 `DIFY_AGENT_IMAGE_READING_ENABLED=true` 在发布和识图联调后开启。迁移时先发布带上述节点的统一入口，再启用此项，避免把图片送到旧配置。工作流、Agent 快照、Skill、原生导出和清单已同步；保存原草稿差异及非思考设置。发布前备份和操作脚本在被忽略的 `work/agent-vision-20261116/`。

## 实际验证

使用隔离数据库、合成员工，从网站后端上传合成故障截图。图中文字含 MDX61B、06 和随机编号 R6N83，用户提问不透露这些答案。

1. 电气助手：22,516 ms 正确识图并返回知识库引用；视觉读取 1.51 秒。知识库独立运行 `2bc02795-2f89-48b0-b406-ddd14100afa4` 实际查询 `SEW MDX61B 故障码 06` 且成功，并非仅从最终回复推断发生过检索。统一入口运行 `3372d1a6-6f9f-4a69-96c9-10be6714dcfb` 全节点成功。
2. 文件 Agent 图片分析：11,144 ms 正确返回设备、型号、故障码和随机编号的 Markdown 表格，实际进入办公工具流程而非快速问答分支。
3. 无图问答：4,234 ms 返回 OK，运行记录确认未执行 agent_image_read。
4. 自动化测试 170 项通过；源码及导出归档凭据检查无匹配，差异空白检查通过，正式站点重载后健康检查 HTTP 200。

## 尚未通过的测试及边界

图片转 Word 的试验中视觉步骤和任务传递成功，但办公 Agent 在工具执行后继续调用模型时遇到上游 `504 stream timeout`，约 184 秒失败。客户端测试在 140 秒超时，未收到可交付 Word，不能将此例描述为完整文件生成已经跑通。记录保存在 `first-e2e-results.json` 和 `office-latest-nodes.json`，只读识图已通过。

本次接入现有 AI 图片预览支持的 PNG/JPG/WebP 等图片；没有新增扫描 PDF 分页成图、原生 CAD/EPLAN 解析或全图纸审查能力。复杂密集图纸、细小文字和遮挡连线仍需高清局部图及人工核对。
