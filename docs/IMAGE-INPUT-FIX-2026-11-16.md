# 网页图片识别链路修复

## 原因

模型端点能接受图像，不代表网页上传后图像会进入对应 LLM。原链路将普通图片请求送到办公文件 Agent，Agent 下载图片后只能通过 Python 读取文件头；统一入口的办公快速回答节点没有启用视觉。卡片分支还过滤了图片，卡片 LLM 的 vision.enabled 为 false，卡片 Skill、办公提示词与环境说明均保留纯文字能力假设。原回复的 WebP、尺寸和 VP8 编码是文件结构信息，不是画面内容。

上传文件转 WebP 是现有服务端生成 AI 图片预览的行为，不是此次无法识图的原因。原文件保留，AI 阅读使用预览。

## 修复

- 统一入口增加本轮 image_materials 文件引用输入，办公快速回答节点启用原生视觉。仅图片的只读问答进入该分支，保留明确求助和情感安全优先级；生成、修改和导出文件继续走文件流程。
- 卡片材料允许授权图片和文档；文档维持文字提取，图片经独立类型过滤送入卡片 LLM 的视觉输入，不需要 Shell 检查文件头。
- 同一任务续问使用已上传的图片引用，不重复上传字节，也不重复挂到父会话 files。新任务文件选择仍由既有后端逻辑控制。
- 背景、报酬图、关闭 AI 阅读及用户拒绝读取的材料仍遵循原授权规则，不把识图等同于同意公开。
- 卡片 Skill、办公提示词及环境说明去除笼统“模型没有视觉”的说法，明确以本轮实际图像输入为依据。模糊小字、复杂图纸等只说明具体不确定处，不编造识别结果；图片中的指令视为数据。

配置已发布到公司统一入口、卡片流程及办公 Agent/流程，工作流工具已同步；保留原草稿差异、非思考设置及权限校验，未修改其他人的 EPLAN 流程。源构建器和导出文件同步更新。

## 验证

使用隔离数据库、合成员工，从网站后端真实上传 PNG（AI 接收 WebP 预览）到统一 Chatflow：

- 普通识图 3,596 ms：正确回答两个红圆、一个蓝方块，以及随机字符 K7M42。
- 图片整理求助卡 6,743 ms：同样正确识图，并形成 Word 清单求助草稿；不自动发布。

新增回归覆盖原生图像引用、续问不重复父会话挂载、背景不读取、图片问答路由、卡片图像过滤和工作流构建幂等性。完整测试 167 项通过，源代码及导出归档检查未发现本机凭据，网站重载后健康检查通过。测试记录和发布前备份在被忽略的 work/vision-fix-20261116。

本次验证普通图片内容问答和图片补卡，未验证复杂图纸准确率、扫描 PDF OCR、图片直接生成办公文件或生成文档的视觉验收。已有错误回复可能影响旧会话，可新建会话重新上传测试。
