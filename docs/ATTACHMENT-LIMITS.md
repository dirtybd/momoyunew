# 对话附件限制

2026-11-05扩容。网站与Dify须一起配置，上传容量与AI读取数量是不同的限制。

| 项目 | 原限制 | 当前 |
|---|---:|---:|
| 网站单文件上传 | 20MiB | 50MiB |
| 每个对话/需求的材料附件 | 30个 | 100个 |
| 个人文件空间（含心情照片） | 250MiB | 1GiB |
| AI每轮材料 | 3个 | 10个 |
| AI单份文档 | 15MiB | 50MiB |
| AI每轮材料合计 | 未单独约束 | 100MiB |
| AI图片预览 | 10MiB | 10MiB（去元数据及缩小后） |

界面沿用MB/GB简写，后台按1024进制计算。权限、可读文件格式和图片4000万像素保护保持。上传图片最多50MiB，实际发给Dify的是去元数据的WebP预览，不是原图。摸鱼空间照片单张20MiB/每帖9张，任务接取者一次提交20个文件，Agent一次返回5个/单个20MiB成果，均为独立限制，本轮没有改动这些数量。

网站限制集中在shared/attachment-limits.mjs，前后端共用大小/数量值。新上传可读材料自动开启AI阅读，达到10个后继续保存但不自动读取，网页明确提示用户到管理附件分批选择；手动启用第11个会在操作时提示。已有附件的读取授权保持。总量在读入所有文件及发送上游之前检查，超出不上传到Dify。取消AI阅读不能撤回已经传给模型的内容。

## Dify本机配置

使用deployment/dify-upload-limits.example.env中的4个环境变量，当前Docker部署通过envs/core-services/shared.env及各服务env_file加载。api、worker、worker_beat、api_websocket须读取同一限制；修改后按现有Compose项目名重建服务，不能只改容器内临时环境。当前Nginx client_max_body_size=100M，网站每次独立上传一个≤50MiB文件，足够覆盖multipart开销。工作室、原Agent及专业Workflow还各有文件数量设置，详情与发布版本见dify-config/multi-agent-handoff.md。

本轮保留并逐项对比原容器环境，仅上传限制允许变化；环境文件备份保存在本机work/backups，不进入Git。重新部署须保留现有数据库/Redis等连接配置和原Compose项目名，不把含凭证的本机env文件复制到仓库。

较大文件仍受Agent沙箱资源、文件格式、页数、上下文和模型能力限制，50MiB能上传不代表任何超长资料都能一次完整理解。大量材料建议分批、说明要核对的页码或范围。


## 2026-11-06 视频与官方背景

- 任务材料与成果：普通文件50MiB、MP4/WebM/MOV视频200MiB；每需求100份材料、每次20份成果及个人1GiB总配额仍有效。
- 摸鱼空间：图片20MiB、视频200MiB；每帖图片与视频合计9项，其中视频最多3项。原API的photos数组兼容保留，媒体项增加kind/mime/size；旧照片默认image。
- 官方背景：仅管理员上传20MiB以内的PNG/JPG/WebP/GIF，转换为去元数据的静态WebP，最长2400×1800。暂存仅上传人可读，确认发布/保存后随卡片公开。替换或清除后旧背景撤回为私人暂存。
- 三类文件共用个人1GiB配额，视频直接流入磁盘；鉴权后支持HTTP Range/HEAD和流式读取，不整段加载200MiB视频。图片处理仍受4000万像素上限保护。

视频仅校验扩展名和容器签名，不转码、不读取画面/声音、不进行AI视频审核，也不自动去除原视频元数据。播放器不能解码时可下载原件，推荐MP4/H.264。匿名不会对画面和原文件自动脱敏，确认公开前需自行检查。视频不作为卡片背景，不向Dify上传；模型只收到文件清单及未读取标记。

后续公网代理需允许至少210MiB请求体，并给大文件上传合理超时；当前Node默认请求接收超时约5分钟，低速网络可按部署需要调整。网站200MiB视频不经过Dify的100M代理，Dify限制只影响AI材料读取。
